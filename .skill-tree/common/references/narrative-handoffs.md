# Narrative review and workflow handoffs

Use a handoff to resume exact work across authoring, independent review and acceptance. Preserve the selected context and the author or operator authority recorded for the current operation.

| Requested mode | Allowed outputs and boundary |
| --- | --- |
| Read-only critique | Findings and recommendations tied to exact source and route. Preserve working records, canon, decisions and queue state. |
| Authorized draft edit | Updated draft artifacts and a change summary within the requested scope. Keep the accepted pin and unresolved owner decisions explicit. |
| Structured independent review | Coverage, evidence and findings for the current proposal. Hold acceptance while a required finding remains unresolved or required evidence is missing. |
| Owner acceptance | Review the exact current proposal, record the observed author decision and use the applicable guarded acceptance procedure. |
| Authorized runtime work | Execute only the admitted build, route and host scope. Report actual results, prerequisites, cleanup and untested lanes. |
| Skill Tree intake | Capture independently actionable follow-up work through the existing authorized intake operation. A review suggestion alone creates no queue action. |

## Minimum handoff record

1. Request mode, task objective, selected work, continuity, period, outcome scope, accepted pin and exact working-source fingerprints.
2. Proposed or changed artifacts, current proposal and reviewed inputs, observed decisions, unresolved blockers and named owner of the next action.
3. Evidence and coverage separated into structural check, semantic review, executed runtime and human playtest. Record actual evidence references and mark absent or stale evidence as a prerequisite.
4. Resume instruction with the exact required input. Recheck changed sources and affected findings before continuing. Preserve unrelated checks and decisions when support remains current.

Draft completion and review completion retain the boundaries of the requested operation. Actual owner acceptance, runtime execution, queue mutation and source control each follow the corresponding authorization.
