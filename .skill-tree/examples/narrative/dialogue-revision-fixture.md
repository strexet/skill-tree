# Dialogue Revision Fixture

The synthetic `scene-dock-inspection` retains the function of granting a dock route under different trust conditions.

| Version | Beat change | Knowledge and outcome |
| --- | --- | --- |
| Original | The captain recites the access rules. | The player hears a summary and can request a route. |
| Focused | The captain first requests evidence. An unsupported answer changes the tactic to a supervised offer. | The captain still knows the public warning only. A receipt unlocks direct access. |
| Larger | An inspectable register exposes why the captain requires evidence. | The player can learn the mismatch. The register adds an interaction and changes disclosure coverage. |

The focused version is recommended for a text-only revision. The larger version gives the register a visible role when the extra interaction fits production scope.

## Adverse cases

On `route-skip-log`, the captain states the exact relay timestamp despite lacking a source. Hold the line until an evidence route exists, or give the captain an evidence-compatible response.

The option labeled “Request supervised access” grants unsupervised access and captain trust in an adverse draft. Compare the offered action and the outcome. Restore supervised state or explicitly revise the choice and explain the new effect before acceptance.
