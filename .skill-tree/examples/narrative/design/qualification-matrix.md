# Narrative fixture qualification matrix

The prior Ridge Pack pilot covers exact snapshot bytes, an observed independent semantic review and selected standalone Ink routes. Planned cases below define distinct outcomes for expansion. An unavailable host or participant leaves the corresponding observation open.

## Playbook checks

| Case | Small positive and adverse fixture | Evidence |
| --- | --- | --- |
| 1. Missing required canon target | Propose a scene with the accepted law, then remove the law from the candidate | Structural guard |
| 2. Draft versus historical source | Edit a working character and resolve the original accepted work pin | Structural history |
| 3. Changed reviewed input | Edit an explicitly reviewed Ink or work file after proposal and compare approval results | Structural freshness |
| 4. Knowledge timing | Compare a route after disclosure with a route that skips the only disclosure before the same line | Semantic trace |
| 5. Witness disagreement | Keep attributed accounts separate and compare an overlapping contradiction between two established facts | Semantic review |
| 6. Optional clue blocks progress | Provide an independent source on the skip route, then remove the alternate source | Semantic and executed route |
| 7. Mutual gates | Give one entry an initial action, then make both quests require the other result | Declared trace and runtime where implemented |
| 8. Incompatible outcomes | Test each ending separately, then assert both mutually exclusive outcomes | Structural state and semantic review |
| 9. Repeat reward | Revisit a report with and without a one-time effect guard | Standalone runtime |
| 10. Lost preparation | Remove an optional setup while the payoff stays mechanically reachable | Semantic craft review |
| 11. Unavailable participant | Compare present and departed character states on the same requested beat | Semantic continuity |
| 12. Unsupported predecessor | Select an allowed result and compare an incompatible imported outcome | Structural and semantic second-work review |
| 13. File rename | Move a complete working record pair while keeping the exact ID and bytes | Structural discovery |
| 14. Joint acceptance | Include mutually dependent revisions together and compare an incomplete package | Structural candidate closure |
| 15. Changed Ink text | Change the authoritative label and regenerate the displayed or compared result while keeping the stable route ID | Standalone runtime and source ownership |
