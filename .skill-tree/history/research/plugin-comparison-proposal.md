# Bounded plugin comparison proposal

The current baseline is execution commit `2a6d240bf6f844d339d246bea57a437e9e3eb7fd` and verified Codex general profile `dd4a66be0c80310cd7412eda5e6603773a28e59861cf5fa731e78f807c21b7f5`. The bounded proposal requires explicit owner agreement and a fixture/input freeze before calibration or comparison. The proposed scope is Codex source-backed invocation in temporary project-owned installations with qualified W1 core, fixed Manual mode and scripted fixture-owner submissions. Manual supplies matched decision evidence and excludes delegated Auto efficacy claims. The product's installation continues to default to an empty plugin registry.

| Application and actual point | Planted case | Clean or adversarial control |
| --- | --- | --- |
| `writing-for-agents` task editorial, Process After | E1 has a buried acceptance condition and awkward operation trigger. Exact acceptance/check mapping, task provenance and dependencies must survive wording improvements. | E2 has clear equivalent wording and distracting formatting. An unnecessary semantic edit, broken check mapping or needless recheck fails the guard. |
| `grill-me` with pinned `grilling` closure, Process After | P1 needs one independently sourced fact and two ordered owner choices. The same T remains held until explicit current acceptance. | P2 introduces a parked round, a stale submitted reply and a scoped edit. Stable IDs, invalidation of affected answers and unrelated-answer retention are required. |
| Separate `writing-for-agents` documentation application, Documentation Audit After Validation | D1 has a stale local link, obsolete command and weak `AGENTS.md` handoff alongside a correct required strict check. | D2 requires the conditional `SKILL-MECHANICS.md` resource for a real skill document. Valid frontmatter, repository navigation and benign house rules remain intact. |
| Original Ponytail, PR Review After | R1 includes a grounded correctness defect, avoidable abstraction and a legitimate repository convention. | R2 has a minimal clean diff, harmless decoys and a sealed review scope. Extra findings or session leakage fail the guard. |

Use the identical fixture checkout, W1 mode, permissible source scope, owner fact cards and operations in each matched pair. Two predefined repetitions run for every fixture in both arms. The core-only arms receive the same opportunity for an independent editorial, interview, docs or review pass without the candidate instructions. The candidate arms use the actual owned hook bridge, pinned source/resource closure, frozen effective parameters and typed current input. Review reuses the same actual full core report for both arms of a repeat. A core report finding the planted target counts as baseline success. Predeclare the same guarded resolution or mark a pair unavailable when a current complete core report cannot be admitted. Ponytail contributes a report on the captured head and keeps the original host-observed context-end receipt.

Use already checked-in originals at Matt Pocock revision `4ae2317ddb22b046e26455e4f9c9b3aaaf62212d` and Dietrich Gebert revision `96608e078b2d5ea607c5c3b8b5a54d1c1fba6846`. The documentation case uses a distinct report-only adapter with exact current audit receipt and inspected source paths. Deterministic qualification of the adapter precedes actual trials. A missing qualified adapter or prerequisite retains an unavailable result. A generic processing role cannot serve as the documentation adapter. The docs arm measures grounded proposals under an owned audit scope. Separately applied repairs in disposable copies require own evidence and are not required for recommendation in the report-only application.

Use 32 matched arm contexts, four shared independent core-review workers, eight fact helpers following the corresponding actual need, eight independent blind fixture judges and two calibrations. The positive calibration requires actual source-backed candidate creation, delivery, return and cleanup. The negative calibration exercises non-activation and may use the allocated independent observer, without candidate dispatch. The maximum is 54 spawned contexts. The bounded request count is 54 spawns, up to 17 sealed delivery follow-ups and 24 interview follow-ups, plus one termination/reconciliation request per created context. The upper bound is 95 spawn/follow-up requests and 54 lifecycle interrupts. One inventory and up to 120 wake-on-event observations give 270 total collaboration calls. No other candidate contexts, paid APIs, provider credentials, live PRs, native Skill tool, Unity, browser or hosted environments. Use the current inherited model/service configuration for all fresh contexts and record actual exposed accounting. Any missing model detail, tokens or monetary accounting stays unknown. Allow at most 60 minutes including a five-minute cleanup reserve, up to three live jobs and up to two arm workers concurrently. Never reroll or retry a case based on an outcome.

Before launch, freeze fixture and oracle digests, actual core source and owned installation/profile, candidate revision/resource closure, adapter policy, blind pair labels/order, script/fact cards, outcomes rubric and timing plan. Negative calibration cannot succeed if a candidate is invoked. Treat unavailable host evidence, a breached hard invariant, open cleanup, timeout or a changed freeze as unqualified. End affected cells without replacement. Stop the overall run when time/call limits or an invalidated common prerequisite prevent honest matching.

The independent judge receives blinded ordered arm artifacts and deterministic oracle outputs. Record target discovery, supported actions, false positives, regressions, workflow gate and provenance, actual elapsed time, exposed usage and separately measured or unknown human rework. A recommendation requires a meaningful correct improvement recurring on both fixed repeats for the planted case, clean controls, no correctness/authorization/readiness regression and an actual supported adapter. An unavailable, contradictory, mixed, or ceiling-limited result remains unqualified. Report a defensible empty eligible set when no candidate meets the criteria. Recommendations remain optional; custom compatible imports stay available.
