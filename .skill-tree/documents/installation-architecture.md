# Installation Architecture

Canonical common contracts/helpers reside in `.skill-tree/common/`; authored operation sections and locked invariants reside in `.skill-tree/templates/`; domain additions and conditional resources reside in `.skill-tree/domains/`. Flavor recipes, compatibility rules, provider destinations and resource ownership reside in `.skill-tree/config/`. The canonical composer emits representative general/web/unity packages under `.skill-tree/skills/<flavor>/` and specialized target packages using the same builder.

Composition merges declared slots/resources deterministically. Locked authorization, selection, checkpoint, evidence and publication invariants cannot be replaced. Identical resources deduplicate; conflicting resources require exact declared replacement hashes. Capability predicates remove inactive resources and instructions before emission. Every installed operation is standalone, including controller leaf contracts/helpers. Source role is explicit in `config/repository.json`; target role never follows a directory named skills.

The resolver reads bounded version/configuration inputs and inventories as data without importing executable configuration. The receipt separates environment identity, source/recipe digests and output inventory/digests. Static compatibility never establishes runner qualification. Concrete project-profile references contain applicable facts/recipes; documentation links to the generated owner rather than duplicating command inventories.

The project installer validates complete composition/ownership before activation. An exclusive install lock, staging, backups and a recoverable journal protect replacement across package, bridge and profile destinations. Multi-provider output reports each provider result; no filesystem-wide atomicity claim exists. Verification checks complete package/bundle inventories, hashes, flavor, bridge identity and profile freshness. Unknown or locally modified content conflicts; unrelated files, queue progress and historical evidence remain preserved.

The maintenance bundle carries the selected domain modules, composer, rules and helpers without the source checkout. Explicit refresh reuses the installation selection, discovers current inputs and activates a verified owned generation at a stopped controller boundary. Unchanged instruction bytes support a receipt-only environment refresh. Required removed recipes remain blocked obligations. No watcher, network download, product hook, global specialization or automatic schema conversion exists.
