The [installation interaction contract](plugin-installation-contract.md) defines a separate optional-plugin stage after verified core installation and requires one exact project proposal before plugin writes. The core-only default and repeat preservation remain independent of plugin consent. Offline/no-write dry-run and installation without skill execution remain binding boundaries.

The execution design separates locked preparation, host invocation outside the lock and guarded result recording. Exact task semantics/source, plugin/dependency revision, profile and review head/base identities support stale-result rejection and idempotent recovery.
