# Core Decision Governance

## Authority and operation scope

The approved core workflow uses research, draft plan, current plan review and acceptance, implementation, required checks, complete review, finding resolution, fixes and re-review. The phases remain inside existing operations. A clean review creates no finding or fix. Operation scope determines the requested output; a documentation, intake or snapshot operation acquires no product implementation authority.

Auto is the approved default for newly activated qualified operation routing. Explicit Manual sends the same question, options, recommendation and researched facts to the owner. Frozen operation/session modes survive resume and project-default changes. Legacy owner-only sessions retain Manual interpretation. Existing authorization, exact selected scope, required checks and publication boundaries remain binding in both modes.

The DG ledger owns question, authority, actual origin, original attempts and current acceptance. The DO frame owns operation phases, current plan/check/review identities, referenced decisions and progress. A DO frame creates no Future queue, controller run or worktree. Bounded state fixtures establish no actual actor execution.

## Actual actor handoff

The host supplies a separate resolver context for Auto decisions. Significant decisions require an independent critic. Substantive disagreement requires an independent arbiter. Reusing an executor, actor or context under another label supplies no independence. Actual host tools create and execute actor contexts outside metadata writer locks; the Python helper prepares and validates records rather than invoking a native tool.

A fresh idle context can be created before the business handoff. Preparation binds the observed creation identity, original DA attempt, frozen role/input envelope and current DG/DO guards. The host delivers the sealed role input after preparation and records the actual matching returned result. Critic inputs include the current resolver answer, public rationale and evidence; arbiter inputs include the current resolver and critic results. Receipt digests bind the supplied material without replacing the material. Missing required capabilities, unavailable actors, uncertain original attempts and out-of-authority choices retain visible prerequisites. Auto never silently changes to Manual.

The workflow CLI freezes actual core bundle/reference hashes and the owned profile digest. Changed execution inputs prevent new actor/business transitions until original attempts are reconciled and the same frame explicitly resumes. Source-generation changes preserve plan bytes, mode and history while invalidating old plan/decision/check/review acceptance. Formatting-only task changes retain the supported semantic equivalence rules.

Manual records the actual owner wait and later submitted answer. A recommendation, silence, preselection or delegated response supplies no owner submission. Controlled qualification distinguishes scripted fixture-owner inputs from real-human approval.

## Current phase identities

Research precedes the plan. Plan acceptance references a separate current specification decision. Changed plan content invalidates affected plan acceptance and downstream evidence. Implementation follows current plan acceptance. Required checks bind current source/head/base and the declared check set. Agent agreement supplies no test result.

Review binds the current complete result and finding identities. Finding resolution accepts a substantiated fix or records an evidence-backed dismissal. Accepted fixes require a changed source digest, actual matching checks and re-review. Changed review or source identities invalidate affected resolutions and readiness. A head or base change with unchanged source retains prior findings for the new review. A clean current review reaches readiness without invented rework.

Repeated unchanged failures or disputes preserve the obligation fingerprint and progress history. Timestamps, actor IDs and repeated endorsements supply no progress. The bounded no-progress rule persists one concrete owner question. Explicit mode changes reconcile original pending actors and retain accumulated history and counts. A clarification-bound frame reconciles the current guarded parent policy through explicit same-frame resume; a parent mode change invalidates previous acceptance while preserving draft plan bytes and historical decisions.

## Evidence and activation

Standalone general/web/unity fixtures exercise the registered core operation set with copied helpers and no source or sibling dependency. Actual-host qualification separately captures observed native calls, actor/context identities, sealed inputs, source/authority bindings and current acceptance. A report-shaped transcript or synthetic actor record cannot replace trusted host observations. Unexposed model, token and cost accounting remains unknown.

Installation consent, package ownership, publication authorization, required checks and external approvals remain separate from delegated decisions. New actor/default-mode activation follows current qualification and the owned stopped-handoff snapshot refresh. Optional plugins add only explicitly configured obligations; core-only installations create no external-plugin hold.
