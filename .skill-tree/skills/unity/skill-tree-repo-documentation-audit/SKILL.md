# Skill-Tree: Audit Documents

Flavor: unity. Read the [concrete project profile](references/project-profile.md).

Read repository-owner rules before action. Exact prioritized selection, required dependency scope, checkpoint integrity, truthful evidence, owner authorization and commit/publication boundaries remain mandatory. A profile, installed flavor or stored checkpoint grants no execution or continuation permission. Read [validation policy](references/validation-policy.md) and [installation profile](references/installation-profile.md).

Read rules, manifest, current documents and [output contract](references/documentation-output-contract.md). Inspect relevant source/configuration/tests using [discovery](references/repository-discovery-checklist.md); document-to-document comparison alone is insufficient. Repair drift and missing required documents from current evidence. Capture confirmed issues in Backlog with IDs and evidence. Read [metadata](references/workflow-metadata.md) and [retention](references/history-retention.md); persist an audit with stable finding IDs, source coverage and unrun checks. Refresh manifest; run the repository metadata consistency validator and scoped prose diagnostics; report corrections, unresolved findings and actual validation. No product implementation is implied.

Generated prose follows [document rules](references/document-rules.md). No unrelated changes, implicit permission or source/sibling dependency.

Prefer deterministic logic and UTF EditMode assertions. Focused PlayMode fixtures cover lifecycle, frames, physics and coroutines. Preserve serialized identity and pinned packages. Verify exact Editor ownership, save/service isolation, authorization, deadlines and cleanup before execution. Player builds, device runs and external services require matching scope. Read [Unity safety](references/unity-safety.md).
