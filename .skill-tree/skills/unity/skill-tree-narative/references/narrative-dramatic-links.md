# Dramatic Intent and Links

A dramatic intent records a proposed or reviewed authoring relationship between scenes or beats. Use a structured record for links likely to cross scenes, works, route variants or later revisions. Keep an ordinary prose note for a local cue where structured tracking adds no useful review decision.

## Record fields

| Field | Meaning |
| --- | --- |
| `id` | Stable intent or link identity. |
| `source`, `target` | Exact scene IDs and optional stable beat keys. Source and target direction follows the declared relationship. |
| `relation` | One of `prepares`, `pays-off`, `poses-question`, `reveals`, `reframes`, `contrasts` or `reprises-motif`. |
| `method` | Optional catalog method key. The method key is authoring guidance outside canon. |
| `scope` | Work, continuity, period and applicable route IDs or conditions. |
| `coverage` | `optional-enrichment` or `required-comprehension`, with known alternative sources and unresolved routes. |
| `function` | Intended dramatic use and the consequence of removing or changing the link. |
| `evidence` | Distinct observations for presentation, chosen interpretation and observed understanding, each with route and source references. |

A preparation link runs from the setup to the anticipated beat. A payoff link runs from the payoff to the earlier setup. Other links run from the authored action or interpretation to the event, question or motif affected by the action. Review a two-way relationship with two explicit links only where both directions are useful. Resolve the declared source and target in the scoped work before treating a link as current. Mark a missing beat or unsupported scope as unresolved.

Dramatic linkage expresses an authoring relation. The runtime owns executable gates. Normative canon dependencies express factual support. Required comprehension can need an alternative setup without making the optional scene a mechanical gate. Keep each category explicit in reports.

A presented clue is an observable build event. A selected interpretation is a player action. Observed understanding requires participant evidence. The player, player character and NPC can have different access to information. Keep per-holder knowledge explicit when the link affects a disclosure.
