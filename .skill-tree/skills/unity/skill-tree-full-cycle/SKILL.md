# Skill-Tree: Full Cycle

Flavor: unity. Read the [concrete project profile](references/project-profile.md).

Read repository-owner rules before action. Exact prioritized selection, required dependency scope, checkpoint integrity, truthful evidence, owner authorization and commit/publication boundaries remain mandatory. A profile, installed flavor or stored checkpoint grants no execution or continuation permission. Read [validation policy](references/validation-policy.md) and [installation profile](references/installation-profile.md).

Follow the [visible owner handoff contract](references/decision-governance.md#visible-owner-handoff) for stops, waits, questions, choices and approvals. Put the exact required action or direct question at the end of the ordinary reply. When a decision has several viable options, compare all options, mark one recommendation inline and explain the recommendation after the option list. When no owner action is required and useful follow-on work exists, offer one concrete next action with exact scope. A short direct continuation reply can select the one unambiguous offer under the existing permission and prerequisite rules.

Read [core decision governance](references/decision-governance.md) before operation work. Newly qualified operation routing defaults to Auto; an explicit Manual selection and every frozen existing mode remain binding. Use research, plan, current plan review/acceptance, authorized operation execution, required checks, complete review, finding resolution, fixes and re-review within the requested operation scope. A clean review creates no fix. Core governance grants no additional implementation, task-selection, installation or publication authority. Auto sends in-scope decisions to a separate resolver, significant decisions to an independent critic and substantive disagreement to an arbiter. Actual native host creation/execution occurs outside metadata writer locks; use the bundled workflow helper orchestration commands to freeze role inputs and record actual producer evidence. Missing capability remains a prerequisite, never a silent Manual fallback. Manual awaits actual owner inputs. Missing owner intent and out-of-authority requests return to the owner in both modes. Repeated unchanged failures/disputes retain progress and produce one concrete owner question. Agent agreement supplies no actual check result or external approval.

Use for a direct full-cycle delivery request. Read applicable repository rules, the manifest and the [full-cycle contract](references/full-cycle.md). Reuse Add Pending, Process Pending, exact Work Through Next or exact-snapshot Implement All, and PR Review Cycle. Use the bundled workflow, processing, validation and PR helpers. Bind one intake batch to the exact processed roots, one isolated controller run and one shared publication. Require all scoped acceptance before opening the PR. Review the full current diff, fix actionable findings, validate and re-review as needed, then merge into develop under the original direct grant and current provider gates. Preserve the exact checkpoint on required questions, blockers or uncertain effects. Resume from verified receipts and established authority. Report the accepted tasks and confirmed publication or the exact prerequisite.

The full-cycle frame binds the original owner request, batch and publication target. Existing leaf frames own decisions and evidence for intake, processing, implementation and PR review. A delegated result grants no new task scope, authorization or external approval.

Read the [plugin binding and invocation contract](references/plugin-invocation.md). Use scripts/workflow-state.py hook-start and hook-next at the full-cycle phases defined in the [full-cycle contract](references/full-cycle.md). Preserve matching bindings at each delegated operation's own boundaries. Empty matching configuration adds no prerequisite. Required unavailable packages, contexts, unresolved attempts or drift hold the current checkpoint. Plugin and resolver results never replace current validation, owner authorization or provider approval.

Prefer deterministic logic and UTF EditMode assertions. Focused PlayMode fixtures cover lifecycle, frames, physics and coroutines. Preserve serialized identity and pinned packages. Verify exact Editor ownership, save/service isolation, authorization, deadlines and cleanup before execution. Player builds, device runs and external services require matching scope. Read [Unity safety](references/unity-safety.md). Read [Unity development](references/unity-development.md) for test seams, lane selection and lifecycle cleanup.

Use the [uGUI checks](references/ugui-testing.md) for the admitted Canvas surfaces.
