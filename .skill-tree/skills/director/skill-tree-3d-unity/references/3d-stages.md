# ArtWorkshop stage controller

Use the stage controller when a 3D request advances a new or existing staged asset. The controller provides explicit dispatch, revision and approval state. The host selects and runs the applicable production tool, records the actual producer, and routes independent visual review. The controller owns ordering, the frozen input packet, current artifact checks, and retry state. The review implementation belongs to the source ArtWorkshop review directory. The synchronization command refreshes the standalone review snapshot before composing installed skills.

## Select scope

Resolve the workshop root, asset and target. Use the existing operating instructions for [references and geometry](3d-workflow.md), [motion and asset types](3d-authoring-roles.md), and [Unity and delivery](3d-unity-roles.md). Use one workflow per asset and authorized scope. Use the latest accepted references for revised work. Catalog lookup and optional stylization precede the references stage. The common entry point follows the full requested graph. A focused entry point stops at the requested stage and consumes the existing accepted predecessor steps.

Use the bundled script, with an input file relative to the workshop root. A source checkout keeps the matching canonical script under `.skill-tree/common/scripts/`.

```sh
python3 scripts/3d-stages.py --root "$WORKSHOP" --run lantern-r1 init --input plan.json
python3 scripts/3d-stages.py --root "$WORKSHOP" --run lantern-r1 next
```

The plan has `schema: 1`, `asset`, `target`, `goal`, optional `motion` and `orthographic` booleans, and a `stages` object. Include exactly the predecessor closure of the goal. A live target contains the exact ID, revision and checkout ID. A fixture target uses a stable string ID. A plan for Unity delivery includes references, clay, blockout, detail, texture, export, Unity and delivery. A moving asset also supplies motion, which starts from detail and joins texture at export. A plan for a clay-only model can stop at blockout or detail. Each stage defines `inputs`, `allowed`, `protected` and `shots`. Inputs use a map of named `{path, sha256}` pins. The other fields are lists of scope descriptions, protected quantities or features, and stable shot IDs. Orthographic plans include front, left profile and top. The planned symmetry checks supply opposite views when applicable. Keep fixed shot roles tied to pose, framing and subject landmarks. Reference requirements freeze `shot-states` keyed by shot. Motion requirements freeze every clip in `clips`, with `minimum-samples` and `max-slip-m` per clip. Geometry requirements freeze protected baselines in `protected-values` with a value and, where applicable, tolerance and unit. Unity requirements name required `controls`, including controls for an animated review scene.

### Configurable validation rules

The workshop root accepts an optional `validation-rules.json` containing `schema: 1` and an `overrides` array. Each entry names a `scope`, a `rule` and at least one of `enabled`, `severity` or `parameters`. The `stage`, `task-type`, `asset-family` and `asset` scopes also name a `selector`. The `project` scope applies to the current workshop root. Precedence runs from catalog defaults through `default`, `stage`, `task-type`, `asset-family`, `project` and `asset`, with the last matching entry controlling each declared field. Entry order has no effect. Duplicate scope, selector and rule combinations, unknown selectors, unknown rules and invalid parameter values reject configuration.

```json
{
  "schema": 1,
  "overrides": [
    {
      "scope": "asset-family",
      "selector": "static-prop",
      "rule": "protected-form",
      "parameters": {"minimum-features": 2}
    },
    {
      "scope": "asset",
      "selector": "lamp",
      "rule": "consistent-views",
      "severity": "advisory"
    }
  ]
}
```

The plan selects `task-type: "creation"` or `"revision"` and a stable `asset` ID. The default task type is creation. The `asset-family` values are `quadruped`, `humanoid`, `other-biological`, `static-prop`, `mechanical` and `unclassified`. A resolved anatomical neutral pose supplies the corresponding family and rejects a conflicting explicit value. A new live motion plan identifies an applicable family from the actual brief and rig. A static prop uses a route without motion. A live motion attempt from a legacy plan requires a current plan before new production or acceptance. Stored accepted records remain readable. The `next` command reports a blocked step when a new downstream handoff requires current motion acceptance.

| Rule ID | Applicability | Evidence and parameters |
| --- | --- | --- |
| `consistent-views` | References | The technical report supplies comparable poses, expressions and anchors. `minimum-anchors` is a positive integer. |
| `protected-form` | Blockout and detail | The technical report supplies candidate measurements against frozen protected baselines. `minimum-features` is a nonnegative integer. Static props default to at least one feature. Planning and dispatch reject a required minimum above the number of frozen features. |
| `biological-segment-lengths` | Motion for quadrupeds, humanoids and other biological subjects | The technical report pins measured Blender lengths. The required tolerance of one micrometre and required severity are protected. |

Run `python3 scripts/3d-stages.py --root "$WORKSHOP" --run lamp-r1 rules` to preview the effective revision, settings, evidence and origin of each decision. The stage packet freezes the effective revision. The technical record references the unique attempt and exact artifact set. The independent review references the candidate digest, including the technical report pin. Required failures hold the stage. Advisory failures remain visible in the attempt for review. Configuration changes that alter a frozen effective revision make the current attempt stale. Reconcile the original attempt and any associated side effects before issuing a new packet. The controller retains the archived packet, measured results and review.

The authored registry in `3d-validation-rules.py` owns stable IDs, applicability, parameter defaults, declared evidence, severity and definition revisions. Add a new stable ID with a matching evaluator and representative fixtures. Increase the definition revision when the contract changes. Retain a retired ID with lifecycle `retired` and keep the retired rule records. A retired definition appears disabled and rejects new enablement. Regenerate standalone copies from the authored source.

#### Length evidence for biological motion

Motion requirements include a `bone-segments` map keyed by the anatomical segments covered by the brief and evaluated rig. Each segment names the rig `bone`, the distinct anatomical `head` and `tail` markers and the positive `bind-length-m`. Cover both sides and all applicable clips. The frozen temporal review supplies the sampled action ranges. The producer measures evaluated joint marker distance and evaluated bone length in world metres at every quarter-frame from start through end, including both sides of each loop seam.

The technical report pins `bone-bind-lengths` and `bone-lengths`. The schema-1 bind receipt has `kind: "biological-bind-lengths"`, the exact admitted detail Blend `source` pin and a `rest-lengths-m` map covering the complete anatomical bone inventory from the admitted source. Measure rest distances in world metres on the admitted geometry or rig. Every measured anatomical bone must match one planned segment and the corresponding frozen bind length.

The schema-1 `bone-lengths` record has `kind: "biological-segment-lengths"`, the exact `scene`, candidate `blend` and `clip` pins, the frozen `segments` map, and `clips` indexed by the planned clip IDs. Each clip contains the exact Blender `action` and ordered `samples`. A sample includes an integer `tick` in quarter-frame units and `lengths` keyed by every segment ID. Each length record holds `joint-m` and `bone-m`. The motion capture pins the same Blender scene, candidate revisions and actions. The independent playback review covers reach and visible deformation alongside the measured evidence.

A separately recorded owner instruction may permit a length change for specific clips and segments. Put the instruction pins under `bone-length-exceptions` in the motion requirements. Each schema-1 decision record supplies `kind: "bone-length-exception"`, `origin: "owner"`, the exact `asset`, nonempty `segments` and `clips` lists, the observed `instruction` and the source `reference`. Each listed segment and clip must exist in the frozen plan. Exceptions cover only the listed pairs and retain every sample and both measurements.

### Neutral symmetry contract

For a new live plan, freeze a top-level `neutral-symmetry` object with a resolved `kind` and a `basis` pin. Use the [neutral modeling rule](3d-workflow.md#exact-symmetry-in-the-neutral-model) to interpret the brief. Ask for clarification when symmetric or intentionally asymmetric intent remains uncertain.

- For `kind: "mirrored"`, record `symmetry_frame`, one or more uppercase `axes`, the exact Blender `scene`, the complete list of Blender mesh names in `subjects`, the closed meshes in `closed_subjects`, a neutral pose type in `pose` and the shared shot state in `state`. Available pose types are `humanoid-t`, `humanoid-arms-down`, `quadruped-square`, `species-neutral` and `object-neutral`. The basis supplies design provenance. Front, side and top belong to the shared neutral reference state. Clay uses the identical set of neutral modeling shot IDs.
- For `kind: "asymmetric"`, record the exact owner-authorized geometry `scope`. Point the basis at a schema-1 decision artifact with `origin: "owner"`, `choice: "asymmetric"`, the matching scope and the observed instruction in `observation`.
- For `kind: "not-applicable"`, record `asset_class: "location"` or `"effect"` and pin the basis for a layout without a modeled subject. Route individually modeled symmetric props through the mirrored contract.

For mirrored references and clay, submit `observations.neutral-reference-symmetry` as a pin for the stage-specific schema-1 receipt. The receipt includes `kind: "neutral-reference-symmetry"`, `state`, `symmetry_frame`, `axes`, a `primary` color or clay sheet pin and `shots` with the exact candidate image pins. The `checks` object maps each axis to inspected `views`, a separately pinned `comparison` overlay in the candidate artifact map, `unmatched_landmarks` and `unmatched_outline_regions`. A passing comparison has empty mismatch lists. The overlay shows reflected geometry landmarks and outlines in the calibrated view or the approved projection. The independent reviewer inspects the overlays and neutral pose before authoring handoff.

For mirrored blockout and detail, submit `observations.neutral-geometry-symmetry` as the pinned receipt from the Blender symmetry inspector. The receipt binds the exact Blender asset hash, scene, coordinate frame, axes, subject list and closed subject list. Both `bind` and `evaluated-neutral` must pass. Every declared plane requires zero unmatched vertices, edges and faces under exact coordinate and connectivity reflection. Each declared closed mesh requires zero boundary and nonmanifold edges, duplicated center vertices and degenerate faces. A visual or numeric finding holds the current stage for repair. The motion stage uses clip evidence and permits intentionally asymmetric phases.

Run the bundled native inspector from the main 3D or Blender geometry package. Select the actual scene, frame and complete scope from the packet. Omit `--closed-subjects` for a scope without closed meshes.

```sh
blender --background candidate.blend --python-exit-code 2 --python scripts/3d-neutral-symmetry.py -- \
  --scene Scene --symmetry-frame world --axes Y --subjects Body --closed-subjects Body \
  --output neutral-geometry.json
```

## Execute the next stage

- `next` lists eligible steps and any outstanding action. `inspect` also exposes historical attempts. Start only a stage in the selected request. Pass `stage` and a stable producer `actor` to `begin`. Retain the returned attempt ID and frozen inputs. A replay returns the existing attempt. Reconcile artifacts and original tool state before repeating a side effect.
- The host dispatches the selected author with only usable stage inputs. Geometry uses approved clay and model files in an isolated authoring context. Keep color out of the geometry handoff. A protected rebuild uses the existing authorization and supplements the matching clay views where helpful.
- `submit` takes `stage`, `attempt`, producer `actor` and a `candidate` with `revision`, named `artifacts`, and a `technical` report pin. The mandatory primary output is color, clay, blend, blend, blend, clip, export, scene, or delivery respectively across the named stages. Visual stages also pin one artifact per planned shot.
- The technical report has `schema: 1`, `attempt`, `stage`, the canonical SHA-256 of `candidate.artifacts` in `artifacts`, a boolean `checks` map, and structured `observations`. Use the named observations below. A technical result supplements native evidence and review. Preserve actual source and runner outputs in the workshop evidence.
- `review` takes the current `stage`, `attempt`, and a separate `review` pin. The record has `schema: 1`, `reviewer`, `attempt`, the returned `candidate_digest` in `candidate`, and a `shots` object. Each shot records the exact candidate `artifact` pin, `result` and a concrete `observation`. Failed shots also identify `finding`, `region` and `expected`. An independent reviewer inspects every required candidate view before the coordinator presents the result.
- `approve` takes the current `stage`, `attempt` and `trusted_host` pin for the actual observed approval. The candidate also pins `review-input` with the existing ArtWorkshop owner-decision contract. The review components and current stage inputs include `workflow-artifacts`, the canonical SHA-256 of candidate artifacts excluding `review-input`. The shared review verifier enforces the current G1, G2, G3, G4 or G5 decision against the exact displayed preview and prior approvals. Preserve host origin and the actual presentation record. A plan with `fixture: true` accepts fixture decisions only and provides no production evidence.
- `repair`, `reconcile` and `revise` take the current `stage`, `attempt` and a `resolution` with a named `method` and concrete `reason`. State repairs return to the same stage and keep previous findings. Reconciliation also requires the original actor and an `evidence` pin documenting the original attempt. Authorized revision or reconciliation can replace `inputs` with current pins. An unchanged finding after the same repair method requires a new diagnostic angle, a different scoped method, or an owner decision. Recheck any dependent stage whose predecessor seal changes. Reuse other accepted receipts.

## Preserve an accepted gameplay requirement

Pin the exact accepted gameplay rule and placement or requirement document in the relevant stage inputs. Name the intended receiver and affected player interaction. For each relevant camera distance, visibility condition, geometry clearance, interaction anchor or movement marker, record the source revision, view or clip, measurement unit, comparison and pass condition. Select the earliest stage that can verify each condition with an appropriate view, blockout or evaluated clip.

Use stage inspection and the existing stage checks for the selected stage, attempt, candidate and frozen inputs. An accepted required check uses the current predecessor pins, selected candidate and observed environment. Treat frozen shots and diagnostic shots as required where the plan requires the views. Record supplementary findings with observed coverage and effect on the named criterion. A supplementary failure cannot substantiate a required pass and a missing required observation holds the affected result. Preserve unsealed and stale diagnostic attempts with the original reason and scope. The workshop stage-check command verifies the staged package inventory and checksums. Delivery references the sealed artifact and the separate receiver check on the exact selected import.

## Surface continuity review

Smooth regions of a 3D model follow continuous contours in neutral and posed form. Flag unintended dents, pinching, sharp folds, sudden changes in curvature, faceting, gaps and overlapping surfaces. The brief can specify deliberate wrinkles, creases, facets, seams and hard edges. Record the design decision and exact region for each exception. Give organic surfaces and deformation regions particular attention, including the jaw and neck, shoulders, axillae, abdomen, hips and joints.

New live blockout, detail and motion plans list at least two additional captures under `requirements.diagnostic-shots`. Each diagnostic ID belongs to the same stage's `shots` list. The list also keeps the planned presentation views. Diagnostic captures use distinct evidence. The independent reviewer records observations for every planned view before owner presentation. Add diagnostic views until the entire shape and occluded regions are covered. For organic forms, include an opposing or rear three-quarter view and a low, overhead or close view that exposes the surface at risk. Inspect the form in a neutral material, check the silhouette and repeat suspect views with grazing light. Compare with cavity or shadows disabled when shading may account for a suspicious line.

For motion, inspect the evaluated surface through each complete clip at normal and reduced speed. Review both sides at matched local phases and inspect the poses immediately before and after maximum bend, contact, release and the loop seam. Capture subframes around a suspected transient defect. Use geometry, weights and intersection measurements to diagnose a flagged region. Exact screenshots, candidate hashes and pose or frame coordinates tie the observations to the current revision. A visible unintended defect in any diagnostic view fails the review, even when the standard presentation views or the numerical checks pass. Recheck the repaired area and the adjacent surface with the same cameras and lighting before accepting the new revision.

### Continuous playback evidence

Every new live motion plan freezes `requirements.temporal-review`. The `views` map binds `left`, `right`, `underside` and `oblique` to four distinct planned shot IDs. The `ranges` map names every planned clip. Each clip freezes the inclusive integer Blender frames `start` and `end`, source `fps` and a boolean `loop`. Legacy live motion requires a new qualified plan for unfinished motion or new downstream execution. Historical approvals and fixture plans remain readable.

The technical observations pin `temporal-motion-capture`. The capture record sets `kind: "temporal-motion-capture"`, names the evaluated Blender `scene`, and pins the exact animated `blend` and `clip` artifacts. Each `clips` entry identifies the Blender `action`, source `fps` and the fixed `views`. A view binds the planned `shot`, `camera` with a distinct `name` and world-space unit `forward` vector, and separate `normal` and `slow` captures. Each capture contains a distinct candidate `video` pin and ordered `ticks` in quarter-frame units. Normal playback includes every whole frame at the source rate. Reduced-speed playback renders every quarter frame and plays consecutive samples at the source rate. Both captures include the final evaluated sample. Inspect a looping clip across a repeated boundary. Extend coverage with close or reverse angles where the primary views hide the surface. Live submission requires local `ffprobe` to decode each video, count frames and verify playback cadence.

The independent review records `playback` by clip, view and speed. Each observation binds the exact `video`, sets `full_playback: true` and records a concrete `observation` and `result`. A loop also needs `loop_boundary_reviewed: true`. Watch every complete sequence for visible jitter, flashes, popping geometry, abrupt silhouette changes and movement discontinuities. A failed observation records the stable `finding`, `region` and `tick`. Failed playback holds the attempt in repair. Recapture previously failed footage and review all required views again before owner presentation. The capture schema verifies coverage and byte identity. The separate playback reviewer establishes visible quality.

### Ventral body continuity in motion

For an organic skinned creature, plan a dedicated underside capture for every required clip, including Walk and Trot when present. Include each capture in both `shots` and `requirements.diagnostic-shots`. The capture frames the full ventral surface from chest through abdomen to pelvis continuously, including the midline and adjoining limb roots. Use neutral materials and add a synchronized low angle where an occlusion hides part of the surface. A local crop supplements the full view. Pin the exact evaluated candidate and clip, camera, frame range and sampling interval. Inspect every frame, sample between frames around maximum compression, contact and release, and check both sides of the loop seam where the clip loops.

Check the bind and evaluated surface where the design calls for continuous skin. Inspect connectivity at the midline and adjoining patch boundaries and look for unwelded coincident vertices or duplicate faces along intended joins. Inspect deform-weight continuity across the midline and comparable weights and gradients on corresponding symmetric regions. Preserve intentional separate shells and seams defined by the brief.

The independent reviewer records visible splits, sharp folds, pinching, ridges or gaps as blocking motion findings, with the clip, frame or subframe, region and pinned capture. Keep the finding open after passing topology, collision or loop checks or confirming the same defect in a prior revision. An intentional wrinkle or seam is acceptable when an explicit owner decision identifies the design, region and applicable clips. Recheck the full underside and neighboring phases after repair. Preserve failed renders in internal review evidence. Share failed diagnostic renders with the owner only on request, labeled with the failure.

## Unity motion acceptance

Every animated Unity candidate uses `requirements.unity-motion-review`, including imported motion and animation-only work. A static live scene records `animated: false` in `scene-receipt`. Freeze the scope before collecting evidence. The scope uses the same `views` and `ranges` as continuous playback evidence. Range keys identify scenario IDs. Scenario names under `cases` match the range keys. Each case defines `kind` as `clip`, `transition` or `control`, and a `sequence` of clip names or actual control events. Every included clip has a full playback case. Include seams for loops, all offered transition directions, blends held between controls, speed changes, reversals and interrupted transitions when the receiver offers the corresponding controls. Start high-risk transitions from multiple phases. Freeze representative permitted start states and speeds. Add close and opposing views where a silhouette, underside or joint is obscured.

Each case freezes `contact` with `max-slip-m` and `max-penetration-m` for the intended scale and floor. An intentionally airborne or contact-free case describes the basis using `no-plant-reason`. Every sample in a contact-free trace has an empty support map. The floor penetration limit defaults to zero for a contact-free case and accepts an explicit `max-penetration-m` tolerance. Declare `regions` covering the whole animated subject. Organic subjects cover limb roots and joints, feet or hands, neck, head, trunk, underside and every tail or appendage. Keep analysis in both root-relative and world or support-relative coordinates as appropriate.

Run the actual saved scene in the intended Unity render and animation profile. Exercise the actual animation, movement, controllers, constraints, skins, materials and floor. Record consecutive whole frames and subframes at normal and reduced playback speeds. Include settling and the poses on both sides of each contact, release, state change, interruption and loop boundary. Show a fixed reference to the floor. A tracking camera supplements the fixed reference. Sample the evaluated surface used by the target renderer. For standard skinning, a skin snapshot plus the target transform can establish world-space vertex positions. For compute or shader deformation, capture the final deformed buffer or equivalent evidence from the actual render path. [Unity skin snapshots](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/SkinnedMeshRenderer.BakeMesh.html)

- **Contact.** Identify the loaded pad, sole or contact patch independently for each limb. Measure horizontal drift between consecutive samples and from touchdown to toe-off relative to the supporting surface. Inspect clearance and penetration, intended contact order, simultaneous support and foot or hand release. A paw left hovering through intended contact is a failure. Compare phase and stride to root travel. Keep intentional pivots and rolls traceable to the reference and track the appropriate loaded part during each pivot or roll. [Footplant constraints](https://research.cs.wisc.edu/graphics/Gallery/kovar.vol/Cleanup/)
- **Surface deformation.** Inspect full-speed playback, subframes and close views for unintended stretching, compression, shrinkage, creases, gaps, intersections, handedness swaps and silhouette changes. Follow the skin and attachments at maximum bend. Check that localized contact correction leaves unrelated regions such as the tail, abdomen and head stable. Compare the same phase against Blender, imported or baked data and the final evaluated Unity output. Confirm the cause with correction, material or lighting isolation when needed.
- **Temporal continuity and trajectory.** Observe the direction and timing of the root and each relevant joint, landmark and attachment from several consecutive samples. At each sample, extrapolate the local trajectory from adjacent prior samples or perform an equivalent velocity and acceleration comparison. Inspect isolated jumps, repeated direction flips, vibration, stalls, reversals without a matching input and one-frame shape pops. Repeat the observation across seams and control changes. An intentional snap, fast action or change in direction remains readable from the lead-in, input and follow-through. Use clip- and region-specific tolerances and inspect flagged intervals in continuous playback from multiple views. Numeric checks locate anomalies. The visible motion and the brief determine whether an anomaly is unintended.

The Unity technical observations pin `unity-motion-capture`. The record identifies `kind: "unity-motion-capture"`, the exact `scene` and `export` pins, the `target` and `play-mode: true`. Capture rows under `clips` use the continuous playback schema for each case. The `action` describes the actual executed event sequence. Each case has a `checks` entry with a `regions` observation map and a candidate `trace` pin. The trace uses `kind: "unity-motion-trace"`, the `scene` pin, the `case` ID and ordered `frames`. Each frame contains the quarter-frame `tick`, `floor-clearance-m` for the lowest measured contact point and a `support` map of currently loaded point IDs to two coordinates in metres tangent to the support surface. Keep support IDs stable through a plant and remove each ID when the patch is unloaded. Record per-region points and detailed diagnostic data in pinned companion artifacts. The controller measures slip and penetration from the ordered trace.

The independent Unity review uses the same `playback` records and adds separate `aspects` observations for `surface`, `trajectory` and `contact` on each view and rate. Review every planned region. A failed playback record identifies the finding, region and tick. Rejected captures cannot serve as new proof. Missing coverage holds Unity for recapture. A demonstrated defect holds the current candidate before G5 or delivery.

### Held intermediate blends

The animated scene receipt records `continuous-blends` as an inventory of actual Unity intervals. The inventory maps each interval ID to the `from` clip, `to` clip and `basis`. An animated scene with zero intervals records an empty map. The frozen `blend-holds` scope matches the exact inventory and adds `samples` for each interval. Use `weight` or `control` for the basis. Each sample maps a normalized value to a separate `hold` case. A hold case lists the ordered clip pair in `sequence`. Every interval includes `"0.5"`. Include `"0.25"` and `"0.75"` when support order, motion or deformation varies across the interval. For a non-linear control, record the normalized control value and inspect the resulting weights when available. [Unity blend trees](https://docs.unity3d.com/6000.0/Documentation/Manual/BlendTree-1DBlending.html)

Start the hold evidence after entry settling. Keep the sampled runtime value within 0.01 of the planned value. A hold range records `loop: true` when either contributing clip has a looping playback case. Play two complete cycles for each looping contributor and review the whole authored interval for finite moves. Inspect the seams, contact, shape, path and cadence for each held value. A transient passage through the value counts as transition evidence. The hold trace adds `held` with the declared `basis` and ordered `samples`. Each sample binds a quarter-frame `tick`, the measured normalized `value` and the contributors' unwrapped `phases` in clip order. A looping phase advances by less than one cycle between adjacent samples and covers at least two cycles across the trace. A pair of looping clips keeps relative phase drift within 0.02 cycles. Two finite clips record `phases: null`. A mixed blend uses a null entry for the finite contributor. Missing or malformed hold samples require recapture. Retain separate entry, exit and interruption cases when the runtime exposes the corresponding inputs.

### Repair routing

The agent compares matched references, evaluated Blender geometry and motion, and the Unity result for every blocking contact or playback finding. Locate the earliest failing source. Correct Unity import, root movement, phase matching, constraints or runtime deformers when the Blender source and references agree. Return to Blender motion, rigging or detail when the native evaluated source fails. Return to references when intended support, timing, direction or form is inconsistent or missing and prevents a correct source. Obtain an owner decision when the fix changes the intended design or exceeds authorized scope.

For a failed Unity motion attempt, `repair.resolution.evidence` pins a `unity-motion-diagnosis` record. The record identifies the exact `attempt`, `candidate` digest, ordered `findings`, and `blender-stage` as `motion` or `detail`. The `unity`, `blender` and `references` records each contain the exact stage `artifact`, `result` of `pass` or `fail`, concrete `observation` and pinned `comparison`. The controller returns `return-to` and reopens the earliest failed stage. Dependent candidates become stale. Production requalifies changed stages and reruns the complete Unity checks before returning to owner review.
