# Skill-Tree: Audit Documents

Flavor: web. Read the [concrete project profile](references/project-profile.md).

Read repository-owner rules before action. Exact prioritized selection, required dependency scope, checkpoint integrity, truthful evidence, owner authorization and commit/publication boundaries remain mandatory. A profile, installed flavor or stored checkpoint grants no execution or continuation permission. Read [validation policy](references/validation-policy.md) and [installation profile](references/installation-profile.md).

Read [core decision governance](references/decision-governance.md) before operation work. Newly qualified operation routing defaults to Auto; an explicit Manual selection and every frozen existing mode remain binding. Use research, plan, current plan review/acceptance, authorized operation execution, required checks, complete review, finding resolution, fixes and re-review within the requested operation scope. A clean review creates no fix. Core governance grants no additional implementation, task-selection, installation or publication authority. Auto sends in-scope decisions to a separate resolver, significant decisions to an independent critic and substantive disagreement to an arbiter. Actual native host creation/execution occurs outside metadata writer locks; use the bundled workflow helper orchestration commands to freeze role inputs and record actual producer evidence. Missing capability remains a prerequisite, never a silent Manual fallback. Manual awaits actual owner inputs. Missing owner intent and out-of-authority requests return to the owner in both modes. Repeated unchanged failures/disputes retain progress and produce one concrete owner question. Agent agreement supplies no actual check result or external approval.

Read rules, manifest, current documents and [output contract](references/documentation-output-contract.md). Inspect relevant source/configuration/tests using [discovery](references/repository-discovery-checklist.md); document-to-document comparison alone is insufficient. Repair drift and missing required documents from current evidence. Capture confirmed issues in Backlog with IDs and evidence. Read [metadata](references/workflow-metadata.md) and [retention](references/history-retention.md); persist an audit with stable finding IDs, source coverage and unrun checks. Refresh manifest; run scripts/validate-repository-documentation.py and scoped scripts/validate-document-rules.py diagnostics; report corrections, unresolved findings and actual validation. No product implementation is implied.

Generated prose follows [document rules](references/document-rules.md). No unrelated changes, implicit permission or source/sibling dependency.

The decision frame uses bounded document/source inspection scope. Plan and review concern the authorized audit and repairs; governance supplies no product implementation permission.

Read the [plugin binding and invocation boundaries](references/plugin-invocation.md). The local ordered manifest describes configured occurrences and bundled source resources. Read the local manifest before routing. Invoke scripts/plugin-hooks.js with an explicit request only for configured matching occurrences at an actual before, during, after or registered named boundary. Empty core-only configuration continues without optional plugin tools or external-plugin holds. Preparation preserves core selection, current plan acceptance and authorization guards; preparation establishes no actual plugin invocation. Missing capabilities and unqualified execution remain explicit prerequisites. Plugin input and effective parameters never replace core scope, authority, required checks or publication consent.

Use focused behavior, component and API fixtures promptly. Browser checks cover actual routing, hydration, storage, service-worker lifecycle, layout, keyboard focus and accessibility when relevant. Verify exact server/build identity and browser policy; mock or screenshot evidence alone never establishes integration. Deployment and physical-device evidence remain separate. Read [Web development](references/web-development.md) for server identity, failure states and browser/hosted evidence.
