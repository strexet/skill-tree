# Canon Review and Owner Acceptance

Start with the selected work, current canon pin and exact draft candidate. Proposal preparation creates a reviewable scope. The proposal does not establish accepted canon. Use [exact review packets](narrative-review-packet.md) when the candidate binds external work, Ink or other reviewed files.

## Review the complete affected scope

Inspect proposed changes and the unchanged normative dependents from the candidate composition and impact report. Resolve exact records and affected work pins. Mutually dependent selected revisions can form one complete package when the dependency closure is valid. Keep optional references and out-of-scope issues distinct from requirements for the selected package.

Ask an independent reviewer to inspect consequential changes against the exact proposal, sources and diff. Record changed and unchanged evidence in the packet. Resolve or dismiss in-scope blockers with traceable reasons. An open blocker or stale bound source holds the package before author acceptance. Apply a scoped fix and refresh the affected review. Retain out-of-scope notes separately.

## Present the owner decision

Show the affected work, alternatives, impact on current and historical pins, review coverage and exact candidate digest. Include the review packet digest for a bound candidate. Separate permission to explore, reviewer concurrence and actual owner acceptance. A review recommendation or an agent-produced fixture receipt cannot supply an owner decision.

For a retcon, state the historical fact, new scope and downstream works affected. For retirement, state which active record disappears from the new composition and which prior snapshots remain readable. Hold a required owner choice while preserving reversible draft work.

## Verify the result

After actual owner acceptance, verify the new snapshot and apply only the authorized work pin change. Resolve representative records in both old and new snapshots. An unaffected work retains the previous pin. A declined or paused proposal leaves drafts and existing accepted history available. Snapshot acceptance supplies no git commit or publication authority.
